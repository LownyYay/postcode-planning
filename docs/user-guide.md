# Работа в сервисе

Как запустить сервер — в главном `README.md`. Здесь — что делать после запуска.

## Вход для жюри

При запуске сервер сам создаёт две готовые учётные записи, чтобы не проходить регистрацию:

| Логин | Кто это | Что видно |
|---|---|---|
| `jury-head` | Глава команды Team-L с правом пересчёта организации | Всё, что доступно главе |
| `jury-member` | Сотрудник Team-L (первый по табельному номеру без учётной записи, на официальных данных — ENG-401) | Интерфейс сотрудника |

Пароли записываются в `orbit/var/jury_access.txt`, путь к нему сервер печатает при запуске. По умолчанию пароли случайные. Чтобы задать их заранее — например, вписать в материалы для жюри, — перед первым запуском задайте переменные окружения `ORBIT_JURY_HEAD_PASSWORD` и `ORBIT_JURY_MEMBER_PASSWORD` (от 10 символов, не только цифры). Учётные записи создаются один раз; на существующей базе повторный запуск их не меняет. Код главы Team-L при этом не выдаётся: у команды одна глава. Отключить создание — флаг `--no-jury`.

## Первая регистрация

1. После сообщения «ОРБИТА запущена» откройте http://127.0.0.1:8000. Терминал оставьте открытым.
2. Откройте файл `orbit/var/team_access.txt`. В нём по одноразовому коду для главы каждой команды. Организатор передаёт каждой главе её код.
3. На вкладке «Регистрация» глава выбирает «Глава команды», вводит код, имя, логин и пароль от 10 до 256 символов. Пароль не может состоять только из цифр или совпадать с логином. Команда определяется кодом; у команды одна глава.
4. В разделе «Команда» глава приглашает существующего сотрудника или сначала добавляет нового. Роли нового сотрудника выбираются из выпадающего списка ролей, которые уже есть в организации; пункт «+ Новая роль…» открывает поле для своей. Сотрудник регистрируется с выданным кодом и ролью «Сотрудник команды».

**Одна роль — одно название.** Написания, которые отличаются только регистром, пробелами, «_», дефисами, точками или «ё», считаются одной ролью: «Дев_опс», «Дев опс» и «ДевОпс» — это «Девопс». Правило действует и при чтении Excel, и в формах, и в CSV факта.

**Коды в интерфейсе.** `ONK-2475` — номер задачи из трекера, `PRODF-7120` — номер инициативы, `ENG-401` — табельный номер сотрудника. Подсказка появляется при наведении на код; полная справка — «Что означают коды» внизу разделов «Задачи и спринты», «Команда» и «Звёздная карта».

Коды глав действуют 30 дней, сотрудников — 7 дней. Повторное приглашение отменяет прежний неиспользованный код. Автоматической отправки приглашений нет.

**Файл с кодами равносилен секрету**: получатель действующего кода может зарегистрировать главу команды. Не добавляйте `orbit/var/` в git (он уже в `.gitignore`) и в общий архив. На Linux и macOS файл создаётся с правами `0600`; на Windows он наследует права папки — держите проект в личной папке организатора.

## Право пересчёта всей организации

Кнопка «Пересчитать прогноз» пересчитывает план всех команд сразу, поэтому одной роли главы для неё мало. Право выдаёт владелец установки из второго терминала, из корня репозитория:

```bash
.venv\Scripts\python.exe orbit\app.py --grant-org-replan ЛОГИН_ГЛАВЫ
```

Отозвать:

```bash
.venv\Scripts\python.exe orbit\app.py --revoke-org-replan ЛОГИН_ГЛАВЫ
```

Право выдаётся только главе команды и действует сразу, без повторного входа. Без него кнопки в интерфейсе нет, а прямой запрос отвечает 403.

## Кто что может

| Действие | Сотрудник | Глава команды |
|---|---|---|
| Задачи, назначения и план | Свои команды и работы, где назначен лично | Все команды |
| Изменение задачи, приоритета, остатка и исполнителя | — | В своей команде |
| Отпуск, болезнь, обучение сотрудника | Видит свои | Сотрудники своей команды |
| Добавление задач и сотрудников, приглашения | — | В своей команде |
| Передача и обмен задачами, помощь часами | — | После согласия двух глав |
| Звёздная карта и риски компетенций | — | Вся организация |
| Отчёт об итогах спринта | — | Только своей команды |
| Загрузка обновлённого датасета и итоговый пересчёт | — | С правом `org_replan` |
| Пересчёт прогноза всей организации | — | С правом `org_replan` |
| Отчёт CSV | Доступные задачи | Все задачи |

Права проверяет сервер: выбор роли в форме не даёт прав другого приглашения. Сотрудник видит и работы в чужих командах, если назначен на них лично — при общем фонде специалистов так бывает.

## Пересчёт занимает время

Любое изменение, которое меняет план — новый сотрудник, задача, доступность, согласованная заявка, — пересчитывает квартал точным решателем. Это до 35 секунд; интерфейс показывает счётчик. Если те же условия уже считались, ответ мгновенный.

## Риски и разбор плана

В обзоре главы — риски, которые считает ядро по готовому плану:

- **Красный** — инициатива не завершается в квартале; названы задачи, которые ей мешают.
- **Жёлтый** — задача сдвинулась относительно исходной базы и потянула зависимые работы. Появляется после фиксации базы, когда план пересчитывается.
- **Оранжевый** — на следующий спринт готово больше работ роли, чем у неё часов, или роли нет ни у кого в штате.

Ниже — «Разбор плана»: узкие места (очки команды или часы роли, выбранные на 100 %), заимствования (часы роли сверх фонда команды — основа заявок на помощь), спрос на следующий спринт и сравнение с жадным планом. Кнопка «Подробный разбор» считает контрфакты: что будет, если принудительно включить отложенную задачу или спасти инициативу. Это 20–40 секунд; план при этом не меняется.

## Отпуск, болезнь и обучение

Если сотрудник выпадает — отпуск на неделю, больничный, обучение, — глава его команды отмечает это в карточке сотрудника: «Отметить отпуск, болезнь или обучение», даты «с» и «по» включительно, причина и комментарий.

- Спринт — 10 рабочих дней. Неделя отсутствия снимает половину часов сотрудника в спринте, день — десятую часть; выходные не считаются. Отсутствие на стыке спринтов уменьшает часы в обоих.
- «Проверить риски» показывает потерю часов по спринтам и последствия для плана без сохранения.
- «Сохранить и пересчитать» сразу пересчитывает план: работа переходит к другим людям с той же ролью, а если их не хватает — сдвигается, и это видно в изменениях плана и в рисках. Причина изменений — «Отсутствие ENG-…: отпуск …, −N ч».
- Отсутствие сотрудника, который работает в нескольких командах, уменьшает его часы во всех; отметить его может глава любой из этих команд.
- «Отменить и пересчитать» возвращает часы.

Все отсутствия команды видны в разделе «Команда». Закрытые спринты отсутствие не меняет: их факт уже внесён.

## Ручное управление

В карточке своей незавершённой задачи глава меняет приоритет, остаток SP, часы по ролям, требования к технологиям и исполнителей.

- **Требование технологий** сужает круг исполнителей: план учитывает только людей, у которых есть и роль, и весь требуемый стек. Если таких нет, задача отменяется с объяснением.
- **Исполнитель**, выбранный вручную, закрывает эту роль в задаче сам. Пустое поле — автоматический выбор.
- **«Не раньше спринта»** задаёт нижнюю границу начала; нехватка ресурса или зависимость могут сдвинуть работу дальше.
- **«Проверить риски»** рассчитывает последствия без сохранения.

Приоритеты и требования к технологиям сохраняются после закрытия спринта; подтверждённый факт заменяет только оценки остатков.

## Согласования между командами

Внутри команды назначение применяется сразу. Передача задачи другой команде, обмен двумя задачами и временная помощь сотрудника часами проходят через «Согласования». Отправка заявки — первое согласие; применяется она после согласия главы второй команды, обмен — целиком. Любая сторона может отклонить заявку.

Если условия изменились, расчёт заявки устаревает: «Обновить расчёт и согласия» пересчитывает последствия и снова требует согласия другой стороны. Завершённую задачу передать нельзя. Помощь часами не увеличивает общий бюджет человека и не поднимает производительность команды в SP.

## Исходный план и факт спринта

Сначала все зарегистрированные главы согласовывают исходный квартальный план в обзоре. Последний голос фиксирует базу — дальше она не меняется при пересчётах, от неё считаются показатели выполнения. Изменение плана или состава глав до фиксации требует новых согласий.

В «Факт и пересчёт» каждая глава в течение спринта вносит **отчёт об итогах спринта** своей команды: выполненные SP, статусы незавершённых задач и потраченные часы по ролям. Остатки SP и часов можно не заполнять: тогда остаток роли — прежний минус потраченные часы, а если часы кончились, а задача не закрыта, — 10 % сметы. Своя оценка главы важнее правила. Отчёт можно менять сколько угодно раз: **сохранение план не пересчитывает**.

### Обновлённый датасет и итоговый пересчёт

После спринта глава с правом пересчёта организации загружает **обновлённый датасет** — тот же Excel, что и в начале квартала, со срезом на конец спринта: статусы, накопленные часы по ролям, оценки, новые задачи и сотрудники, новая строка производительности команд в `Team_history`. Загрузка тоже ничего не пересчитывает. Карточка «Данные спринта» показывает, что изменит датасет:

- закрытые задачи и сменившиеся статусы, часы, потраченные за спринт;
- SP команд из новых строк `Team_history`;
- новые задачи и сотрудники; задачи, которых в датасете нет, — они остаются в плане как были;
- откуда возьмутся данные по каждой команде и задаче и где датасет расходится с отчётами команд.

Когда данные собраны, кнопка **«Итоговый пересчёт спринта»** один раз строит новый план. Датасет — официальный срез: по задачам, которые в нём есть, статус, часы и остаток берутся из него, при расхождении с отчётом команды — тоже из него. Отчёт команды используется для задач, которых нет в датасете, и для SP команды, если в `Team_history` нет новой строки. Без датасета спринт можно закрыть по отчётам всех шести команд, как раньше.

**Старое не удаляется.** Задачи и сотрудники, которых нет в новом датасете, остаются; закрытые спринты, их факт и исходная база сохраняются. Если данные за уже закрытый спринт оказались неточными, загрузите исправленный датасет в блоке «Исправить закрытый спринт»: факт этого спринта заменяется исправленным, план пересчитывается, база не меняется.

После пересчёта в «Итогах спринта» видно, **какие отклонения вызвали изменения**: задачи, не завершённые в срок, не начатые или выполненные меньше плана спринта, закрытые раньше плана, работа вне плана; какие квартальные цели ушли за квартал или вернулись в него; как изменилась производительность команд.

До фиксации исходного плана в том же разделе можно загрузить другой **исходный датасет**: он заменит исходные данные, задачи и сотрудники из сервиса сохранятся. План пересчитывается кнопкой «Пересчитать план»; до этого он помечен как устаревший, и согласовать его нельзя.

Проверочный датасет после спринта можно получить генератором: он «проводит» спринт по плану, а задачи из `--delay` оставляет без движения.

```bash
python orbit/scripts/sprint_dataset.py --sprint 1 --delay DB-202 --out orbit/var/dataset_s1.xlsx
```

После итогового пересчёта план строится со стабильностью: оставшаяся работа раскладывается как можно ближе к прежнему плану, а не заново. Выполнение спринта считается по правилам ядра: SP задачи засчитываются в доле потраченных часов (до закрытия — не больше 90 %), при закрытии — весь остаток. SP, которые указала глава, показываются рядом для сверки и обновляют производительность команды на следующие спринты. Процент квартала — доля инициатив, которые исходная база обещала завершить.

### CSV факта

Кнопка «Шаблон CSV» скачивает текущие задачи команды. UTF-8, разделитель `;`:

```csv
sprint;team_sp;task_id;status;remaining_sp;role;remaining_hours;spent_hours
```

Первая строка без `task_id` — для общего `team_sp`. Для задачи — одна строка на роль; статус и остаток SP во всех строках задачи совпадают. Остатки в шаблоне пустые — заполняйте их, только если ваша оценка точнее правила. Статусы: `ToDo`, `InProgress`, `Done`; у `Done` остатки нулевые. Десятичная часть — через точку или запятую.

«Загрузить CSV» проверяет файл и заполняет форму; сохраняется он только после «Подтвердить факт команды». Пустые файлы, чужие задачи, дубли ролей и противоречивые значения отклоняются.

### Отчёт CSV

«Отчёт CSV» выгружает одну таблицу: строка на задачу, команда, статус, SP и часы, исполнители, начало и конец, прогноз, причины риска, принадлежность исходным целям, плановые SP по шести спринтам и фактические часы. Учитывает права текущего пользователя. Открывается в Excel (UTF-8 с BOM, `;`). Текст, похожий на формулу, экранируется.

## Звёздная карта

Узлы перетаскиваются мышью или касанием, фон двигается, расположение сбрасывается. Положения хранятся в браузере. С клавиатуры: стрелки двигают выбранный узел, Enter открывает карточку.

Вкладка «Риски компетенций» начинается с организации в целом: сколько технологий знает один человек (BF = 1) и два человека (BF = 2), и уникальные профили — люди, у которых нет коллеги с похожим стеком (кластеризация DBSCAN ядра). ## Доступ по сети

По умолчанию сервер слушает только `127.0.0.1`. Для сетевого доступа ставьте его только за HTTPS-прокси и задавайте `ORBIT_COOKIE_SECURE=1` — переменная добавляет cookie флаг `Secure`, но сама TLS не включает. Прокси должен сохранять исходный `Host`.

Docker, сборка из корня репозитория:

```bash
docker build -f orbit/Dockerfile -t orbita .
```

```bash
docker run --rm -p 127.0.0.1:8000:8000 -e ORBIT_COOKIE_SECURE=1 -v orbita-data:/app/orbit/var orbita
```

Самостоятельного сброса пароля и смены главы в интерфейсе нет.
