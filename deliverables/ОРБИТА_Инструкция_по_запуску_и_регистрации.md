# ОРБИТА 3.0.0

## Инструкция по запуску и регистрации

Инструкция предназначена для владельца локальной установки, глав команд и сотрудников. Команды выполняются из корневой папки проекта, если явно не указано иное.

## 1 Что понадобится

- Windows, macOS или Linux;
- Python 3.11 или новее;
- интернет при первой установке Python-зависимостей;
- современный браузер;
- права на запись в папку проекта;
- файл `data/dataset.xlsx` в составе поставки.

По умолчанию ОРБИТА работает локально по адресу `http://127.0.0.1:8000`. Не публикуйте этот HTTP-порт напрямую в интернет.

## 2 Состав данных установки

Перед первым запуском проверьте наличие:

```text
requirements.txt
data/dataset.xlsx
config/planner.yaml
config/aliases.yaml
orbit/app.py
orbit/start_windows.bat
orbit/start.sh
```

Каталог `orbit/var/` появится автоматически. В нём будут храниться рабочая SQLite-база и секретный файл первоначальных приглашений. Этот каталог нельзя добавлять в git или передавать в общий архив.

## 3 Быстрый запуск в Windows

1. Распакуйте проект в личную рабочую папку владельца установки.
2. Убедитесь, что команда `python --version` показывает Python 3.11 или новее.
3. Запустите двойным щелчком `orbit\start_windows.bat`.
4. Скрипт создаст виртуальное окружение, установит зависимости и запустит сервер.
5. Браузер откроется только после успешного ответа сервера на проверку готовности.
6. Не закрывайте окно терминала, пока работает ОРБИТА.

Если ассоциация `.bat` запрещена политикой системы, откройте `cmd`, перейдите в корень проекта и выполните:

```text
orbit\start_windows.bat
```

## 4 Быстрый запуск в macOS или Linux

1. Откройте терминал в корне проекта.
2. Проверьте версию Python командой `python3 --version`.
3. Выполните:

```text
sh orbit/start.sh
```

4. После сообщения о запуске откройте `http://127.0.0.1:8000`.
5. Терминал оставьте открытым.

## 5 Ручная установка

Ручной способ полезен для диагностики и контролируемого обновления.

### 5.1 Создание окружения

Windows:

```text
python -m venv .venv
.venv\Scripts\activate
```

macOS и Linux:

```text
python3 -m venv .venv
source .venv/bin/activate
```

### 5.2 Установка зависимостей

```text
python -m pip install -r requirements.txt
```

Зафиксированные расчётные зависимости включают PuLP 3.3.2, HiGHS 1.15.1 и openpyxl 3.1.5.

### 5.3 Запуск сервера

```text
python orbit/app.py --open-browser
```

Без автоматического открытия браузера:

```text
python orbit/app.py
```

Изменить порт:

```text
python orbit/app.py --port 8080
```

Использовать отдельную тестовую базу:

```text
python orbit/app.py --db orbit/var/test.db
```

Остановить сервер можно сочетанием Ctrl+C в терминале.

## 6 Проверка успешного запуска

Откройте в браузере:

```text
http://127.0.0.1:8000/api/health
```

Ожидается JSON с `status` и версией `3.0.0`. Затем откройте главную страницу:

```text
http://127.0.0.1:8000
```

Первый запуск рассчитывает исходный план и может занимать 13–20 секунд. После изменения состава или ограничений расчёт может продолжаться до 35 секунд. Не запускайте второй сервер на той же базе во время расчёта.

## 7 Первоначальные коды глав

После первого запуска сервер создаёт:

```text
orbit/var/team_access.txt
```

В файле находится по одному одноразовому коду для главы каждой команды.

Правила обращения с файлом:

- владелец установки передаёт каждой главе только код её команды;
- файл не отправляется в общий чат и не включается в архив проекта;
- на Linux и macOS файл создаётся с правами `0600`;
- на Windows проверьте, что папка проекта доступна только владельцу установки;
- код главы действует 30 дней;
- повторно использованный код отклоняется.

## 8 Регистрация главы команды

1. Откройте `http://127.0.0.1:8000`.
2. Перейдите на вкладку «Регистрация».
3. Выберите роль «Глава команды».
4. Введите одноразовый код своей команды.
5. Укажите отображаемое имя.
6. Придумайте логин длиной от 3 до 80 символов. Допустимы латинские буквы, цифры и символы `.`, `_`, `@`, `+`, `-`.
7. Укажите пароль длиной от 10 до 256 символов.
8. Пароль не должен состоять только из цифр и не должен совпадать с логином без учёта регистра и пробелов по краям.
9. Подтвердите регистрацию и войдите.

Команда и роль определяются приглашением. Выбор другой роли или команды в форме не меняет права кода. Для каждой команды разрешена одна зарегистрированная глава.

Отклонённая регистрация из-за неверного пароля не расходует приглашение.

## 9 Приглашение существующего сотрудника

1. Войдите как глава команды.
2. Откройте раздел «Команда».
3. Найдите сотрудника из исходного датасета.
4. Нажмите действие приглашения.
5. Передайте полученный код конкретному сотруднику безопасным способом.

Код сотрудника действует 7 дней и связан с конкретным профилем. Повторная выдача отзовёт прежний неиспользованный код.

## 10 Добавление и приглашение нового сотрудника

1. В разделе «Команда» выберите добавление сотрудника.
2. Укажите настоящее отображаемое имя.
3. Выберите роли, навыки, грейд и долю занятости.
4. Сохраните сотрудника.
5. Выдайте ему приглашение.
6. Передайте код пользователю.

При добавлении проверяются роли, часы и принадлежность команде. Не создавайте фиктивные профили только для устранения предупреждения: отсутствующая роль должна отражать реальный способ выполнения работы.

## 11 Регистрация сотрудника

1. Откройте страницу ОРБИТЫ.
2. Перейдите на вкладку «Регистрация».
3. Выберите роль «Сотрудник команды».
4. Введите код, полученный от главы.
5. Укажите имя аккаунта, логин и допустимый пароль.
6. Завершите регистрацию и войдите.

После входа сотруднику доступны «Мои задачи», «План команды» и «Команда». Организационные риски, карта навыков, согласования и управление задачами ему не передаются.

## 12 Выдача права на пересчёт организации

Обычная роль главы не разрешает пересчитывать всю организацию. Право выдаёт владелец установки из второго терминала.

Windows:

```text
.venv\Scripts\python.exe orbit\app.py --grant-org-replan ЛОГИН_ГЛАВЫ
```

macOS и Linux:

```text
.venv/bin/python orbit/app.py --grant-org-replan ЛОГИН_ГЛАВЫ
```

Отзыв права:

```text
python orbit/app.py --revoke-org-replan ЛОГИН_ГЛАВЫ
```

Право применяется сразу. Повторный вход не требуется. Без права кнопка пересчёта отсутствует, а прямой запрос возвращает 403.

## 13 Фиксация исходного квартального плана

1. Зарегистрируйте необходимых глав.
2. Каждая глава проверяет план и риски в обзоре.
3. Каждая зарегистрированная глава подтверждает исходный план.
4. Интерфейс показывает число полученных и требуемых голосов.
5. Последний голос фиксирует baseline атомарно.

Если до последнего голоса изменился план или состав зарегистрированных глав, прежние согласия становятся неактуальными. После фиксации baseline не изменяется при дальнейших пересчётах.

## 14 Первый рабочий цикл

1. Глава проверяет задачи своей команды и при необходимости выполняет предварительный расчёт рисков.
2. Межкомандные передачи и помощь оформляются через раздел «Согласования».
3. После завершения спринта каждая из шести команд подтверждает факт.
4. Факт можно заполнить вручную или загрузить из CSV-шаблона.
5. Последнее действительное подтверждение закрывает спринт, обновляет историю и пересчитывает прогноз.
6. В обзоре сравниваются baseline, факт и новый прогноз.

## 15 Проверка ролей в разных браузерах

Для одновременной проверки двух глав или главы и сотрудника используйте разные профили браузера либо обычное и приватное окно. Новый вход в тот же аккаунт отзывает прежнюю сессию, поэтому две активные сессии одного пользователя не поддерживаются.

## 16 Запуск тестов

Из корня проекта:

```text
python -m pytest tests
python -m pytest orbit/tests
node --check orbit/static/app.js
```

UI smoke:

```text
python orbit/scripts/ui_fixture.py > ui-fixtures.json
node orbit/tests/ui_smoke.mjs ui-fixtures.json
```

Серверные тесты используют временный локальный порт. Среда запуска должна разрешать привязку к `127.0.0.1`.

## 17 Docker

Сборка выполняется из корня репозитория:

```text
docker build -f orbit/Dockerfile -t orbita .
```

Локальный запуск с постоянным томом:

```text
docker run --rm -p 127.0.0.1:8000:8000 -v orbita-data:/app/orbit/var orbita
```

Для работы за HTTPS-прокси:

```text
docker run --rm -p 127.0.0.1:8000:8000 -e ORBIT_COOKIE_SECURE=1 -v orbita-data:/app/orbit/var orbita
```

Переменная `ORBIT_COOKIE_SECURE=1` только добавляет флаг `Secure` к cookie. Она не включает TLS.

## 18 Обновление установки

1. Остановите сервер сочетанием Ctrl+C.
2. Скопируйте всю папку `orbit/var/` в резервное место.
3. Обновите программные файлы и зависимости.
4. Не заменяйте рабочую папку `orbit/var/` пустой.
5. Запустите сервер и проверьте `/api/health`.
6. Войдите существующей учётной записью.
7. Перед рабочим использованием выполните тестовый просмотр плана и экспорта.

## 19 Частые проблемы

| Симптом | Проверка и действие |
|---|---|
| Страница не открывается | Убедитесь, что терминал с сервером работает и используется правильный порт |
| Порт занят | Запустите с другим `--port` или остановите прежний процесс |
| Первый запуск долгий | Дождитесь завершения точного расчёта; нормальное время 13–20 секунд |
| Нет кнопки пересчёта | Выдайте главе право `org_replan` |
| Код регистрации отклонён | Проверьте срок, роль, команду и повторную выдачу приглашения |
| Старая вкладка получает 409 | Обновите страницу; состояние изменилось и `revision` устарел |
| После нового входа старая вкладка получает 401 | Это штатно: новый вход отзывает прежнюю сессию пользователя |
| CSV не принимается | Скачайте новый шаблон, сохраните UTF-8 и разделитель `;`, не меняйте заголовки |
| Нет исполнителя требуемой роли | Проверьте роль, навыки, доступность и согласованную помощь |
| Сервер не запускается с прежней базой | Восстановите резервную копию `orbit/var/` и проверьте права записи |

## 20 Минимальная проверка после регистрации

Глава должна увидеть шесть разделов, организационный план, риски и звёздную карту. Сотрудник должен увидеть три раздела и только разрешённые задачи. Прямое изменение чужой команды должно возвращать 403. После выдачи `org_replan` кнопка пересчёта должна появиться без повторного входа.

Перед демонстрацией дополнительно пройдите сценарий TS-13 из `docs/test-scenarios.md`.
