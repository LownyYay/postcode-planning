# HTTP API ОРБИТЫ 3.0.0

## Назначение

API обслуживается тем же локальным HTTP-сервером, что и статический интерфейс. Формат прикладного обмена — JSON, кроме импорта и экспорта CSV. Изменяющие запросы после входа требуют действующую сессию, CSRF-токен и актуальный номер `revision`.

## Общие правила

- `Content-Type` для JSON: `application/json`, допускается параметр `charset=utf-8`.
- `NaN`, `Infinity` и `-Infinity` отклоняются как неверные JSON-значения.
- Ошибка содержит поле `error`; внутренние детали клиенту не передаются.
- Устаревшая версия состояния возвращает 409.
- Сотруднику данные фильтруются по доступным командам и личным назначениям.
- Глава читает организационный план, но меняет только свою команду.

## Публичные маршруты

| Метод | Маршрут | Ответ или действие |
|---|---|---|
| GET | `/api/health` | `{status, version}`; актуальная версия 3.0.0 |
| GET | `/api/auth/status` | Массив названий команд без признака регистрации главы |
| POST | `/api/auth/register` | Регистрация по одноразовому приглашению |
| POST | `/api/auth/login` | Пользователь, CSRF и cookie сессии |

## Структура плана в `/api/state`

Каждая задача содержит `entry`:

| Поле | Смысл |
|---|---|
| `status` | `done`, `planned`, `beyond`, `partial` или `blocked` |
| `start` | Первый спринт работы |
| `end` | Спринт завершения или прогноз |
| `reasons` | Причины включения, переноса или блокировки |
| `fragments` | Доли работы по спринтам, SP, часы и назначенные люди |

План верхнего уровня также содержит:

| Поле | Смысл |
|---|---|
| `validation` | Нарушения независимого валидатора; у корректного плана список пуст |
| `engine` | `optimal` или `fallback_greedy`; признак стабильного пересчёта |
| `risks` | Красные, жёлтые и оранжевые предупреждения |
| `analysis` | Узкие места, заимствования, спрос ролей и сравнение движков |
| `metrics` | Плановые, фактические и прогнозные показатели |
| `star` | Bus Factor и уникальные профили DBSCAN |
| `baseline_approval` | Прогресс голосования до фиксации базы; после фиксации `null` |

## Фиксация базы и пересчёт

`POST /api/approve` учитывает голос главы. До последнего голоса база не создаётся. Последний голос и baseline сохраняются атомарно. Повторный голос с тем же актуальным состоянием не создаёт новую версию.

`POST /api/replan` принимает только `revision` и необязательный `project_id`. Изменение конфигурации через пользовательский маршрут запрещено. Операция журналируется с командой и именем инициатора.

## Коды ответа

| Код | Значение |
|---:|---|
| 200 | Успешная операция |
| 400 | Неверные поля или значения |
| 401 | Нет действующей сессии |
| 403 | Недостаточно прав, неверный CSRF или запрещённое происхождение |
| 404 | Неизвестный маршрут или объект |
| 409 | Конфликт `revision` или устаревшее согласование |
| 413 | Слишком большое тело запроса |
| 415 | Неподдерживаемый `Content-Type` |
| 500 | Непредвиденная серверная ошибка |

## Ограничения

API предназначен для одного процесса ОРБИТЫ с локальной SQLite-базой. CORS и внешняя интеграция не требуются. Для сетевого доступа сервер размещается за HTTPS-прокси; встроенного TLS нет.
